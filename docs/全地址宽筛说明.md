# 全地址宽筛版本说明

本次基于 Daniel-Wu-1/tron_vanity_address_generation 的提交
`59dfbc1d8d971898c360af8912a9f22c6fd1de7e` 增量修改。
secp256k1、Keccak、SHA256、Base58 编码算法保留原实现。

## 启动

需要 NVIDIA CUDA 显卡。AMD RX 5700 XT 不能运行这个原项目的 CUDA 内核。

```powershell
python -m pip install -r requirements.txt
python tron_vanity_gpu.py
```

1. 前缀/后缀模式：逗号分隔多个目标，每侧最多 8 个，重复目标自动去重；超过上限报错，不截断。
   前缀包含开头的 T，区分大小写。两侧内部为 OR，两侧之间默认 AND，可选 OR。
   只有一侧有条件时，另一侧不会使 OR 无条件命中。允许相容的前后缀重叠。
2. 靓号模式：逐项填写最低长度，例如填 `10` 表示该规则检查 `10～34` 位，留空关闭。
   不再输入统一范围或 y/n。每项示范值只作参考，不会自动启用；全部留空会要求重新填写。
   检查整个地址的任意位置。长度接受 2～34 的整数，普通数字顺子最多 9。
3. 运行分钟数：`0` 持续运行。计时从实际搜索开始，不包括内核编译、自检和起点初始化。
   Ctrl+C / 到时后停止新批次，处理完已经提交的 GPU/CPU 候选再退出，所以退出可能稍晚。

### 逐项输入示范

界面逐项显示例子、参考等待时间和示范填写值。下面的时间按任意位置、约 3.92 亿地址/秒
和近似随机 Base58 分布估算，不是本版本真机性能测量或固定出号保证。
同时开启多项后，实际速度及候选处理压力会改变；分组的估算尤其粗略。

| 规则 | 示范填写 | 示例 | 参考平均时间 |
| --- | ---: | --- | --- |
| 纯豹子，区分大小写 | 8 | `88888888`、`AAAAAAAA` | 8位约4分钟；9位约4小时 |
| 同字母忽略大小写 | 10 | `aAaAAAaaAa` | 10位约30～35分钟；11位约16小时 |
| 连续分组 | 8 | `aabbccdd`、`aaabbbbcccc` | 18位约1小时（粗估） |
| 普通数字顺子 | 8 | `123456789`、`98765432` | 8位约50分钟；9位约4.4天 |
| 数字循环顺子 | 8 | `789123456`、`123456789123` | 8位约12分钟；9位约12小时 |
| 数字周期重复 | 10 | `123123123`、`12121212` | 10位约1.8小时 |
| 含字母周期重复 | 13 | `ABCDABCDABCD` | 13位约1小时 |
| 纯数字回文 | 10 | `1234554321` | 10位约11～13分钟 |
| 含字母回文 | 18 | `ABCDEFGGFEDCBA` | 18位约50～60分钟 |
| 任意连续纯数字 | 16 | `5837291648357291` | 16位约25分钟 |

例如只收 8 位以上纯豹子和 16 位以上纯数字：第一项填 `8`、最后一项填 `16`，中间全部回车。
运行前会列出实际开启的规则和各自范围。`rule_minima` 配置中缺少的项或值为 0 表示关闭。
旧的全局 `min_len/max_len/rules` 配置仍兼容，便于旧测试和脚本继续使用；新菜单只生成独立门槛配置。

## 第一阶段保留的结构

这里“有意义”定义为下面的结构族，不声称覆盖所有人的主观审美。
后续细筛程序可以基于保存的原始片段、位置、组长度自行排名。

| 规则 | 判断 | 例子 |
| --- | --- | --- |
| 连续相同字符 | 原始字符完全相同 | `88888888`, `AAAAAAAA` |
| 同字母忽略大小写 | 仅字母；折叠后相同 | `aAaAAAaaAa` |
| 连续分组 | 相邻不同字符的连续段，每组至少 2 位；组长不限，不限制为 2～4 组 | `AAccBBDd`, `aaabbbbcccc`, `11122233`, `1122233344455566` |
| 顺序分组（属于连续分组） | 去重后的组字符逐个 +1 或 -1，可有单字符组 | `abbccddeeff`, `abbcccddddeeee`, `112233445566` |
| 数字顺子 | `1..9` 内连续递增/递减，不回绕 | `12345678`, `987654321` |
| 数字循环顺子 | 正向允许 9→1，反向允许 1→9；无须一定跨越边界，普通顺子也可同时属于此类 | `123456789123`, `987654321987` |
| 数字周期重复 | 全部 1～9，周期 2～4，至少重复两遍，允许末尾不完整一遍；全同字符不归此类 | `123123123`, `12312312` |
| 含字母周期重复 | 至少一个字母，忽略大小写，其他周期条件同上 | `ABABABAB`, `ABCABCABC`, `A12A12A12` |
| 纯数字回文 | 片段全部 1～9，支持奇数/偶数长度 | `12344321`, `123454321` |
| 含字母回文 | 片段至少含一个字母，忽略大小写，支持奇数/偶数长度 | `ABCDEFGGFEDCBA`, `AB123321ba` |
| 连续纯数字 | 任意排列，不要求重复、顺序、对称；仅匹配片段为数字，地址其他位置不限制 | `5837291648357291` |

分组、周期、回文统一折叠大小写。`AAAAaaaa` 是一组，不拆成两组。
顺序分组按字母/数字实际顺序判断，不跨数字/字母、不回绕；不会产生不存在的 Base58 字符。
任意位置几个零散重复不等于连续分组；也不会用旁边随机字符把片段凑到 8 位。

一个地址只写一行。主匹配取最长；同长度用规则优先级和起始位置确定。
`matches` 保留不同类型和不同位置的独立匹配，同类型被更长匹配包含的短结果被合并。
上限是匹配窗口上限，不会因原始连续段更长而丢掉它里面满足范围的片段。
新配置每个匹配还保存 `rule` 和 `minimum_length`，结果顶层保存完整 `rule_minima`，
`schema_version` 为 2。结束统计和 `.stats.json` 的 `saved_by_type` 包含各类型的保存数量；
同一个地址可计入多个类型，因此类型合计不等于唯一地址数。

## 性能和候选完整性

- 精确模式编译为单独的内核变体；后缀先走 `base58_tail()`，失败即跳过完整编码。
  OR 同时启用前缀时，后缀失败还需检查前缀，因此额外完整编码是必要成本。
- 全地址模式每个地址必须完整 Base58 编码，预期慢于尾号模式，实际差异只能在 NVIDIA GPU 测量。
- GPU 使用连续段扫描、周期短窗口和回文中心必要条件，避免逐个长度窗口做完整分类。
  CPU 只处理粗筛候选，用独立进程批量校验私钥/地址和分类。
- 每条规则的独立门槛直接传给 CUDA；不是先统一用最低门槛筛出大量地址再交给 CPU。
  数字与含字母周期/回文在 GPU 阶段分别检查字符条件。CPU 仍负责最终类型、完整片段及验证。
- CPU 分类改用连续段边界、周期扫描和回文中心，避免默认范围逐地址检查全部 378 个窗口。
  每个位置、每种类型保留最长匹配，再合并包含关系；位置、大小写标签、组长度和独立匹配保持原语义。
- 分类进程按可用 CPU、进程亲和性和常见 Linux 容器配额设置，预留 2 核，最少 1 个进程。
  16 个可用核通常使用 14 个分类进程；Windows 最多 61 个。
- 后台协调线程提交分类任务并保存结果；哪个任务先完成就先保存，不等待队首慢任务。
  同一轮已完成任务合并刷盘，保留 JSONL 的 fsync 和磁盘去重。GPU 调度通过有界队列交接候选。
  每批最多 128 个候选，分类任务最多为进程数的 2 倍，额外缓冲最多为进程数的 4 倍。
  状态栏的“分类任务”和“缓冲”单位都是批；只有持续处理不过来、缓冲也满时才阻塞 GPU 提交。
- CPU 暴力生成关闭；随机起点生成、GPU 命中后的 CPU 加密校验保留。
- 两个 CUDA Stream 保留；仅复制实际命中的结果数，使用 pinned memory。
- 正常启动默认 M=24，不比较 M 参数速度，不执行批次预热测速。仅在编译失败时依次尝试 M=16、M=8。
  保留 GPU/CPU 正确性自检；初始每批 128 步，运行中根据候选量缩小批次。
  命中索引改为完整链索引，避免原先 4 bit 点编号无法表示 M>16。
- GPU 每次运行前保存曲线状态。结果缓冲溢出时恢复并重放同一区间，缩小批次；
  单步仍装不下时扩容到该步实际数量。重放不重复统计已搜索地址。
- CPU 队列有界。候选过多时报警并等待，不会自动加大长度或丢弃候选。
  因此不能同时承诺任意宽松规则、零丢弃以及 GPU 永不等待；过载时优先保留结果。
- 起点准备完成后直接进入正式搜索；性能对比仅由用户手动运行 `benchmark.py`。
- 不能保证断电、磁盘损坏或 GPU 驱动崩溃时保留全部数据。

## 输出

`命中地址/matches_时间.jsonl`：UTF-8，每行一个 JSON 对象，适合 Python/BAT 后处理。
私钥/地址只放在顶层，`matches` 内没有重复私钥。

主要字段：`time`（UTC ISO 时间）、`address`、`private_key`、`type`、`length`、
`content`、`normalized`、`start`、`groups`、`group_lengths`、`tags`、`matches`、
`source`、`verified_by`、`classified_by`、`schema_version`。
`start` 为从 0 开始的字符位置，文件用 `position_base: 0` 明确说明。
`source: GPU` 表示 GPU 生成，验证与分类均为 CPU。

例：`aaaaaaaaabbbbbbbbbb` 会记录长度 19、组数 2、组长度 `[9,10]`。

配套文件：

- `.stats.json`：地址/秒、候选/秒、分类数、保存数、溢出重放数、等待时间、GPU/CPU 利用率均值等。
- `.index.sqlite3`：地址去重索引，避免无限运行时用内存集合不断增长；不是另一份私钥结果。
- `.pending.jsonl`：仅处理异常时生成，保存尚未确认处理的候选与配置供恢复；它不是已验证的最终结果，可能与成功写入部分重叠。

## 验证与 benchmark

```powershell
python -m unittest test_vanity test_pipeline -v
python verify_kernel.py
python benchmark.py --seconds 2 --repeats 5 --pipeline-seconds 30
```

`verify_kernel.py` 需要 CUDA：检查所有链索引、多步/多次启动的 GPU/CPU 地址一致性，
并将植入结构样例及随机样本交给实际 CUDA 粗筛，对照 CPU 分类，检查漏筛。

`benchmark.py` 从固定原始提交读取旧内核，在同一卡上比较原版后缀、新版后缀及全地址模式，
分别测 M；输出 `benchmark_results.json`。普通后缀最佳实测速率下降超过 15% 时返回失败，
不把它当作通过。GPU 内核速度和新增完整流水线速度分开记录，不把两种口径混用。
基准产生的独立随机起点仅用于测速，搜索结果仅写在正式流水线输出中。

无需 NVIDIA 显卡的辅助检查（Windows）：

```powershell
python verify_kernel.py --compile-only
# 可选：安装 ziglang 后，把实际 CUDA 粗筛函数提取为原生 C++，在 CPU 执行覆盖测试。
python -m pip install ziglang
python verify_kernel.py --host-screen
```

离线编译和主机执行都不能替代 CUDA 真机运行测试或性能测试。
